# Culture Here — 전국 문화·교육·체험 프로그램 탐색 서비스

전국의 문화·교육·체험 프로그램을 통합 검색하고 지역과 관심사에 맞게 발견할 수 있도록 돕는 웹서비스. 전국 단위 데이터 수집과 서비스 확장을 목표로 설계한다.

## 현재 포함
- 반응형 랜딩/검색 화면
- 키워드 검색
- 카테고리, 대상, 비용, 지역 필터 UI
- 예시 프로그램 카드 및 상세 모달
- 빈 결과 상태 및 필터 초기화
- 모든 데이터는 테스트용 샘플임을 UI에서 명시
- GitHub Pages 배포 workflow 및 CI 검증 workflow

## 개발 로드맵
1. **전국형 브랜딩 및 공개 MVP** — 완료
2. **GitHub Pages 배포** — 완료
3. **통합 데이터 구조/API 수집 프레임워크** — 기본 틀 추가; 실제 API별 매핑 및 호출은 검증 후 연결
4. **실제 API 연동** — 확보한 API부터 응답, 조회 범위, 이용 조건을 검증하고 연결
5. **API 자동 발굴 파이프라인** — 공공데이터포털·중앙부처·지자체·공공기관·도서관·문화시설·교육기관의 신규 프로그램 API를 주기적으로 탐색, 기존 목록과 중복 비교, 후보 평가, 신청 필요 여부 분류
6. **데이터 정규화 및 중복 제거** — 출처별 수집, 공통 필드 매핑, 중복 판정, 데이터 품질/최신성 관리
7. **전국 데이터 범위 확대** — 실제 확보된 데이터 지역만 표시하고, 데이터 미확보와 프로그램 없음을 구분
8. **검색/사용성 개선 및 수요 검증** — 실사용 검색 품질, 프로그램 상세, 출처 링크 검증
9. **운영/수익화 검토** — 사용량과 수요 확인 이후 광고·제휴 등 저비용 수익 모델 검토

## API 수집 정책: 지역별 관리 폐지, API 중심 통합

API를 지역별로 개별 관리하지 않는다. **API별 Collector/Adapter를 하나씩 관리**하며 각 API의 공식 문서와 실제 응답을 확인해 조회 범위를 판정한다.

각 API의 `queryScope`는 다음 중 하나로 기록한다.
- `nationwide`: 전국 데이터 조회가 가능하므로 지역 반복 호출 없이 전국 수집을 시도한다.
- `region-required`: 지역 필터가 필수이거나 전국 조회가 불가능함이 확인된 경우, 단일 수집 코드에서 지역 목록을 반복 요청한다.
- `unknown`: 조회 범위가 확인되지 않았으므로 자동으로 전국/지역 반복 조회를 단정하지 않고 문서 또는 테스트로 확인한다.

지역 목록은 API별 별도 코드나 별도 운영 단위가 아니다. 지역 반복 요청이 필요한 API의 설정값으로만 사용한다. 전국 조회가 가능하면 한 번(페이지네이션이 필요한 경우 페이지 단위) 수집하고, 이후 서비스 내부에서 지역 필터링한다.

## API 자동 발굴 기준
- 프로그램 정보(문화, 교육, 강좌, 행사, 공연, 전시, 체험, 모집/신청) 제공 여부를 우선
- 전국 또는 지역 조회 범위, 제공 필드(일정, 신청기간, 대상, 비용, 장소, 모집상태), 갱신주기, API 방식, 인증/신청 조건, 이용 약관, 연동 난이도 기록
- 기존 API와 중복되지 않는 후보만 추가 검토
- 신규 후보가 발견되면 공식 출처, 데이터 범위, 적합성, 우선순위, 신청 절차 및 활용 목적 문구를 정리
- 최종 제출, 본인 인증, 계정 권한이 필요한 단계는 사용자 확인 필요
- API 키와 비밀값은 공개 코드에 저장하지 않으며 환경변수/비밀 저장소로 관리

## API 통합 프레임워크
- `api.js`에 공통 지역 목록, API 상태 상수, 공통 프로그램 데이터 정규화, API별 adapter 생성, 조회 범위에 따른 수집 분기, 중복 제거의 기초 구조를 둔다.
- 실제 API endpoint, 인증 방식, query parameter, response parser는 공식 문서와 실 응답을 확인한 후 source adapter별로 구현한다.
- 승인/인증 준비가 되지 않은 API는 수집하지 않고 상태를 통해 skip한다.
- `nationwide`는 전국 조회, `region-required`는 지역 반복 요청, `unknown`은 조회 범위 확인 전 수집 보류로 처리한다.
- API 수집 결과는 원본 API가 제공한 데이터만 정규화한다. 추정/가짜 값을 채우지 않는다.
- 이 프레임워크는 현재 정적 GitHub Pages UI와 아직 연결되지 않은 개발 기반 코드이며, 실제 API가 통합되었다는 의미는 아니다.

## 현재 API 현황 (기존 기록; 범위 재검증 필요)
- 문화포털 문화정보 조회서비스: 전국 범위 후보, 신청/승인 대기 상태를 확인하며 진행
- 전국 평생학습강좌 표준데이터: 미신청
- 문체부 소속 및 산하기관 교육정보 API: 기존 기록상 인증키 발급됨; 실제 조회 범위는 검증 필요
- 국립박물관 문화행사 통합정보 API: 미신청
- 국립어린이청소년도서관 공개모집 API: 기존 기록상 인증키 발급됨; 실제 조회 범위는 검증 필요

지역별 API 운영/관리 계획은 취소한다. 위 API 기록에 남아 있는 대구 관련 표시는 기존 신청/키 관리 이력일 뿐, API가 대구 데이터만 반환한다는 확정 의미가 아니다. 전국 조회 가능 여부는 각 API 문서와 실제 응답으로 판정한다.

## 로컬 확인
`index.html`을 브라우저에서 열면 됩니다. `api.js`는 현재 프레임워크이며 실제 API endpoint와 응답 parser가 연결되기 전에는 웹 UI에서 데이터를 가져오지 않습니다.

## GitHub Pages
GitHub Actions를 Source로 사용하며 `.github/workflows/pages.yml`에서 배포한다.

## 보안
- API 키, 비밀번호, 개인정보, `.env` 파일을 Git에 커밋하지 않는다.
- 브라우저에 노출되는 API 키는 비밀이 아니다. 민감한 키는 백엔드 또는 GitHub Actions Secrets 등 안전한 환경에서 관리한다.
- 공개 저장소에 올리기 전 secrets와 로그를 검토한다.

## 문화포털 API 자동 수집 설정

현재 첫 실데이터 소스로 문화포털 문화정보 조회서비스를 연결하는 수집기와 6시간 주기 GitHub Actions 워크플로가 추가되어 있다. 수집기는 최근 30일~앞으로 180일 범위의 프로그램을 조회하고 `data/programs.json`으로 저장하며, 웹 화면은 해당 파일을 읽는다.

### 최초 인증키 설정(필수)
1. GitHub 저장소의 **Settings → Secrets and variables → Actions**로 이동한다.
2. **New repository secret**을 선택한다.
3. Name에 `CULTURE_PORTAL_API_KEY`, Secret에 문화포털 API 인증키를 입력한다.
4. Actions → **Collect Culture Portal API Data** → **Run workflow**로 최초 실행한다.
5. 실행 결과에서 수집 성공 여부를 확인한다. 성공 시 데이터 파일 커밋과 Pages 재배포가 자동 진행된다.

인증키는 공개 저장소 코드에 넣지 않는다. 현재 API 수집 워크플로는 인증키가 없으면 수집을 건너뛰므로, 인증키 설정 전 웹사이트는 실데이터 대기 상태로 표시된다.


## API 통합 관리

API 목록과 인증키 관리 원칙은 [`docs/API_REGISTRY.md`](docs/API_REGISTRY.md) 및 [`config/apis.json`](config/apis.json)을 기준으로 한다. 실제 인증키는 저장소에 커밋하지 않으며 `.env.example`은 환경변수 이름만 제공한다.
